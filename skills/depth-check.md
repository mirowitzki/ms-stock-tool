# 技能：质检关·第四道防线 —— 深度核查（depth-check，防偷懒/防写水）

> 花名：坎特（团队花名册见 CLAUDE.md）

> 来历（2026-06-19，用户第三次点名）：报告反复写成"放大版摘要"——每章像一份执行摘要，先给结论、摆几个数字、收尾，没有把一章真正挖透。前三道质检（check_numbers 对账 / fact-check 防幻觉 / discipline-check 防成见）分别管对账、数字真假、立场，**唯独没有一道管"深度"**。一份每个数字都对、立场也中性、但通篇停在摘要高度的报告，能全过前三关、却依然不合格。这一关专治这个。
> **触发：出 PDF 前，在 check_numbers + fact-check + discipline 之后、作为最后一道；🔴 清零才出 PDF。** 对完整报告（`<TICKER>_公司完整报告.md`）必过。

## 总则

- **独立上下文是命门**：depth-check agent 只喂 ① 报告草稿 ② 原始材料（`filings/` 招股书+年报+公告、`financials/`）③ 本技能。**不喂作者写报告时的推理**——它的职责是拿草稿去对原始材料、判断"草稿用没用够材料里的料"。
- **它判的是深度、不是对错**：数字真假是 fact-check 的事、立场偏颇是 discipline 的事。这一关只问一件事——**这一章是把问题挖透了、还是只写了个摘要？材料里明明有的料，是不是被一笔带过了？**
- **只挑错、不改写**：逐章输出深度评级 + 指出"这里有料没用"，主 Claude 据此重写。
- **标尺 = RKLB / 超卓航科(688237) 深版**：那种密度才算合格——每个判断后面跟具体产品/客户/年份/数字/机制/画面，一章一章深挖、写透一章再下一章。
- 防卡死规矩同全局：grep 定位 + 小段读、频繁小步工具调用、禁整篇一次性读 40 万字文件。

## "放大版摘要"的七个症状（逐章扫，命中即扣分）

1. **执行摘要高度**：整章都是主旨句/结论句，缺中间层——没有"为什么、怎么发生的、靠什么机制、有什么证据"。读完只知道结论、不知道推导。
2. **断言而非展示（违反 show-don't-tell）**：写"护城河来自客户认证""毛利率受价格战压制"却不展开认证要几年/谁审/换供应商成本多高、不展开年降具体降几个点/哪个客户/哪年的真实降幅。每个判断后面应跟具体数字/机制/名字/画面。
3. **材料明明有料却被略过**：原始材料（招股书/年报/公告）里有具体的产品清单、客户名与占比、历史事件时间线、分部数据、管理层原话、交易细节，草稿却只给一句概括。这是最硬的偷懒证据——agent 要 grep 出"料在 filings 第 X 行、草稿只字未提或一笔带过"。
4. **章节空心化/重复**：同一块内容（控制权、估值、某事件）在多章重复摆，每章都浅、没有一章真正负责把它讲透；或业务概述里把治理/估值整段铺开、导致后面对应章节空心。
5. **历史/演变缺故事线**：发展历程只列几个时间点，没讲"从什么起家、每一步为什么、怎么长成今天"；重大资本运作（收购/重组/募投）只给结果、不给来龙去脉与对价/估值/对赌细节。
6. **财务只摆数不解释**：财务章把指标列出来，但没有"逐年走一遍、每个拐点背后是什么、利润质量的水分在哪、现金流和利润为什么背离"的 walk-through。
7. **篇幅与材料严重不匹配**：采集到一大堆带行号的细节，报告却很短——产出远小于投入，是写水的直接信号（但长 ≠ 深，注水的长也算偷懒，看的是单位篇幅的信息密度）。

## 逐章深度清单（每章给评级）

对九章逐章判：

- **业务概述**：每个产品线有没有讲清是什么、什么工艺、什么价值定位、具体产品名？分部收入结构有没有摊开？□
- **发展历程**：有没有真实的起家故事 + 逐步演变 + 重大资本运作的来龙去脉（不只时间点）？□
- **行业与竞争**：行业结构、集中度、具名竞争对手、护城河机制（为什么对手进不来）有没有展开？还是泛泛而谈？□
- **商业模式与盈利引擎**：经营/采购/定价/结算流程、关键变量（年降/原材料/模具经济）有没有带数字和机制讲透？□
- **资本配置**：有没有逐年 CFO vs capex vs 分红 vs 并购的走账 + 每笔大动作的判断？□
- **治理与诚信**：股权结构、家族/关键人、关联网、ST 清单、重大治理事件有没有具体到名字、时点、金额、机制？□
- **财务全貌**：四柱 + 会计可信度有没有逐年/逐季 walk-through、利润质量取证、口径辨析？□
- **投资分析与估值**：driver 拆解、三情景（每个情景的故事+假设+对应数字）、反向 DCF、premortem 有没有写实？□
- **风险全景**：每条风险有没有机制 + 缓释 + 触发信号，还是一句话清单？□

## 输出格式

逐章一行：【章名 + 深度评级（✅深挖 / 🟡偏摘要 / 🔴写水）+ 1-2 句诊断 + "这里有料没用"的具体指针（filings 第 X 行有 Y、草稿只给了一句）】。
最后给：① 全报告整体评级（合格 / 不合格）② 最该补深的 3 章及各自最该补的料 ③ 一句话——这份报告离 RKLB/688237 深版还差在哪。
**最后一行：通过 / 不通过（任一章 🔴 即不通过）。**

## 流程（主 Claude 操作）

1. 草稿 + 前三关过完后，起独立 depth-check agent（喂草稿 + filings + financials + 本技能）。
2. 收清单 → 对每个 🔴/🟡 章节回原始材料补深（**作者第一手读、不要再二手合成采集摘要——二手合成正是写水的根源**）→ 重写 → 复跑 depth-check 直到无 🔴。
3. 反复出现的偷懒模式升级进 `reviews/LESSONS.md`。

## 配套铁律（写报告时就守、别等被查）

- **深读不外包**：采集可以外包（拉数字、定位行号），但"读穿一章、把料织成故事"是作者的活、不外包——外包深读＝必然写水。采集 agent 给的是带行号的事实清单，作者要据行号回原文第一手读、再下笔。
- **一章写透再下一章**：深度优先于覆盖面，宁可少写一章、不可章章皆浅。
- **show don't tell 是硬约束**：每个判断后面必须跟具体数字/机制/名字/画面；写完自检——把所有主旨句删掉，剩下的中间层证据撑不撑得起结论？撑不起＝写水。
