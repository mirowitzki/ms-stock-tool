# 技能：复盘 / Post-mortem（让工具越学越智慧）

> 2026-06-10 大改版：从"出新数据回头看看"升级成**可记分的复盘体系**。
> 复盘的对象有三层：**driver 预测**（反馈最快）→ **单家公司论点** → **这台机器本身**（校准）。
> 核心改变：决策时就把预测钉成可判对错的格式；复盘时先盲评再对照；错误归类而不是笼统反思；
> 所有打分汇进 `reviews/CALIBRATION.md`，季度复盘机器本身。

---

## 目的

每分析一家公司就沉淀一份决策记录；触发条件出现时回头对照——**情景兑现了吗、概率准吗、我当时漏了什么**——把收获提炼成可推广的教训，存进 `reviews/LESSONS.md`，并把打分存进校准台账。
学的公司越多、教训库和台账越厚；分析新公司前先读教训库 + 原型判例库，工具就越聪明。

两条底层认识（设计这套体系的原因）：
- **记分优先记 driver、不记股价。** 一年只有十几个判断、股价噪声又大，按股价记分要三五年才有统计意义；driver 层预测（放量节奏、利率走向、控制权落定、份额变化）每季度都能打对错——反馈快、噪声低。股价只做慢变量参考。
- **区分决策质量与结果（防 resulting）。** 给了 Bear 30% 概率而 Bear 兑现了，单次不证明当时判断错；十次里兑现八次才证明概率错。反过来，靠运气对的判断也不算对。先问"按当时可得的信息，这个判断该不该下"，再问"结果如何"。

## 动作一：建决策记录（估值章定稿时做，自动沉淀）

写 `analyses/<代码>/decision.json`。除原有字段（ticker / date / currency / verdict / value_range / current_price / probabilities / thesis_key_variables / drivers / key_risks / decision / in_circle_of_competence）外，**2026-06-10 起每家必写以下新字段**：

```json
{
  "review_by": "2026-09-15",
  "archetype": ["题材壳/控制权转型期权", "无主治理/控制权事件"],
  "entry_watch": { "low": 4.0, "high": 8.0, "unit": "元/股", "note": "价格只是必要条件时在此说明",
    "invalidation": [
      { "event": "治理红旗被公告级证据证实（如实控人立案/占用认定）", "source": "公司公告/监管文书", "status": "open" },
      { "prediction_id": "P1", "triggers_when": "miss", "event": "承重预测证伪即带作废" }
    ] },
  "predictions": [
    {
      "id": "P1",
      "claim": "定增去杠杆是中性情景成立的胜负手",
      "metric": "定增审核注册进度",
      "threshold": "2026-12-31 前获交易所审核通过+证监会注册",
      "check_by": "2026-12-31",
      "source": "公司公告",
      "scenario_link": "base",
      "status": "open"
    }
  ],
  "odds": { "downside_to_low_pct": -96, "upside_to_high_pct": 76, "to_center_pct": -63, "ratio_up_vs_down": 0.79 },
  "expected_irr_5y": { "to_center_pct_per_year": -18.0 },
  "premortem": {
    "up": "假设5年后回看，这个偏空判断错得很惨（错过大牛股）——最可能的剧情……",
    "down": "假设5年后回看，这个判断让人亏了大钱——最可能的剧情……"
  }
}
```

各字段的规矩：
- **review_by**：最迟复盘日。新财报 / 新公告 / 价格进观察区会更早触发，这是兜底闹钟。通常设在下一个财报季后两周。
- **archetype**：原型标签（查 `reviews/ARCHETYPES.md`），让"越学越智慧"能按同类判例检索。
- **entry_watch**：**数字化**入场观察区（喂 `review.py` 的价格触发）。价格不是充分条件时（如还需定增落地、需放量证据），在 note 写清——进区只触发"机会复盘"、不等于买入信号。非价格型条件留 null。
- **entry_watch.invalidation（2026-07-04 新增——价格带作废条件、摊平预承诺；Miller 2008 对不透明杠杆金融股一路摊平到 −55%、Ackman 在 Valeant 传票落地后又加仓的教训）**：写死什么事件让这个价格带作废。规矩：① 每家 **3-5 条封顶**、每条必须与该股 ch9 top_risks 或 premortem.down 同源（600327 就是母体债务违约/质押处置类、300996 就是内部人减持超阈值类），禁止通用红旗清单复制粘贴；② 两类条目——**事件型** `{event, source(查证处), status: open/triggered}`（与 predictions 四元组同纪律、写得出查证处才许写）、**引用型** `{prediction_id, triggers_when: hit/miss, event}`（复用 predictions 的结算、不另建状态机）；③ 触发判定**只认公告/监管文书级证据**（fact-check 证据分级前两级）、媒体传闻不触发；④ 任一 triggered ⇒ 带作废：价格再进带时 `review.py` 提示"这是刀不是折扣、须完整重分析"（路由到动作二流程 7 的完整重分析、不做机会复盘），重分析后重设新带。
- **predictions（核心）**：可判对错的预测，四元组＝**指标 + 阈值 + 期限 + 查证处**。每条到期必须能明确判 兑现 / 未兑现 / 未决，不许写"盯一盯""关注"这种打不了分的。优先写 driver 层。阈值是你的判断线（这正是把判断钉死的意义），但引用的基数必须是已核实的事实。status：`open` → 复盘时改 `hit` / `miss` / `unresolved`。
- **odds / expected_irr_5y**：**代码算、别手算**（机械推导自 current_price 与 value_range；odds=到区间两端的不对称度，IRR=(价值/现价)^(1/5)−1）。它们是赔率标尺、不是预测。
- **premortem（事前验尸）**：两段——往上错（错过）与往下错（亏钱）的最可能剧情。写不出具体剧情＝情景想象宽度不够，回去补。新分析必写；存量公司在首次复盘时补写。
- 概率写下时同步注明参照的 base rate（`reviews/BASE_RATES.md`）——先报同类事件的历史频率，再说这家为什么偏离。

## 动作二：单家公司复盘（触发即做）

**三类触发**（`python scripts/review.py` 扫描）：
1. **新数据**：decision.date 之后出现新季报 / 新公告；
2. **到期**：`review_by` 到期、或某条 prediction 的 `check_by` 到期；
3. **价格**：月度收盘进入 `entry_watch` 区间——这是**机会复盘**（价格到了，论点还成立吗？是机会还是我漏了什么？），价格大跌而论点未变恰恰是最该重看的时刻。

**流程（顺序是命门）**：

1. **盲评先行**：先派一个独立 agent（干净上下文，只喂最新 financials / quarterly / decision.date 之后的新公告 / 最新价，**不喂旧 decision.json、旧报告的结论**），让它独立给出：关键变量现状 + 对论点方向的判断。读资料守防卡死规矩（grep 定位 + 小段 Read，禁整读年报）。
2. **再开旧 decision.json 对照**：diff 盲评结论 vs 原判断。分歧点就是复盘的主菜——是现实变了，还是当时就看错了？
   **盲评反驳义务（2026-07-04 加）**：盲评的方向判断与旧 verdict **不同向**、而复盘后 verdict 仍不动时，`review_<日期>.md` 必须含一段"为什么盲评错了"的书面反驳（引具体证据、逐点回应）；**写不出反驳＝按流程 7 做完整重分析**——不许"看过了、维持原判"四个字带过（可口可乐 1998 教训：持有免检 15 年）。
3. **逐条给 predictions 打分**：`hit` / `miss` / `unresolved`（未决的顺延 check_by、留在 decision.json）。driver 层优先。
3.5 **论点漂移对照（2026-07-04 加）**：把旧 `_thesis.md` 四步（核心论点 / 认知差 / 价值困在哪靠什么释放 / 主变量）当勾选清单，**逐项标 存活 / 已死 / 被新理由替换**，在 `review_<日期>.md` 里落成四行强制表（`review.py` 复盘提示时会打印旧 _thesis 当对照底稿）。**主变量或认知差任一项"被替换"而 verdict 不变＝论点漂移**，强制走流程 7 的完整重分析——理由换血必须付出与新买同级的论证成本（Ackman 把 Valeant 渠道欺诈重定义为"公关问题"、理由换了结论不变；300085 那次论点实质换血守住靠自觉、现在靠这条机制）。
4. **误差归类**（只对 miss；五类药方完全不同）：
   - **A 数据错**（取数 / 计算 / 口径）→ 修代码、加质检项；
   - **B 生意理解错**（游戏规则 / 护城河 / driver 判断错）→ 修框架、补研究、记原型判例；
   - **C 概率校准错**（方向对、概率离谱）→ 修 base rate、调概率习惯；
   - **D 不可知意外**（当时无法获得的信息）→ 不修，如实记录；
   - **E 纪律违反**（清单本可拦住但没执行）→ 修流程、升级检查清单。
5. **防 resulting 自检**：写一句"按当时可得信息，这个判断该不该下"。该下而结果坏 = 记录但不自我鞭打；不该下而结果好 = 照样记 miss（流程意义上的）。
6. **登记**：把每条已结预测 append 进 `reviews/CALIBRATION.md` 打分行；提炼 **≤1 条可推广教训**进 `reviews/LESSONS.md`（描述成"一类情形"、不绑定个股）；**若教训属于 E 类或反复出现，升级成 `fact-check.md` / `discipline-check.md` 的查项——教训的终点是清单，不是散文**。
7. **产出**：写 `analyses/<代码>/review_<日期>.md`（盲评结论 / 分歧+盲评反驳 / 打分表 / **_thesis 四步存活表** / 归类 / 教训）；更新 decision.json（predictions 状态、invalidation 状态、必要时顺延 review_by、补写 premortem）。**判断本身要改 → 不在复盘里偷偷改**，做完整重分析（重抓数 → 重写相关章 → 重设情景 → 过质检关）。

## 动作三：机器级复盘（季度一次，或每攒约 10 条已结预测后）

复盘对象从单家公司升级到**这台机器本身**。读 `reviews/CALIBRATION.md` 汇总：

1. **概率校准表**：所有已结预测按当时声称的概率分桶（≤30% / 30-60% / ≥60%），各桶实际兑现率 vs 声称概率——回答"我说 45% 的时候到底是不是 45%"。
2. **verdict 分布与命中**：偏贵 / 偏低判断各占多少、事后方向命中率——回答"这台机器是纪律还是系统性偏空"（背景：截至 2026-06，14 家里 11 家结论偏贵，待检验）。
3. **误差类别分布**：A-E 哪类最多 → 对应升级（代码 / 框架 / base rate / 清单）。
4. **升级动作写回**：LESSONS 铁律区、BASE_RATES、检查清单、原型判例库。
5. **横截面综合（2026-07-05 加——单个案子看不见的模式，合起来看）**：把全部在册公司按原型/产业链/verdict 摆一张表，回答三问——① 哪类原型的判断赔率最好/最差（该多做哪类、少做哪类）；② 已验证的优势口袋（如破净+好资产+治理催化）还成立吗、有没有新口袋浮现；③ 同一个论点押了几次（AI 资本开支线上有几家＝集中度，接 O19 暴露地图）。上次全系统体检人肉做过一次、发现了深价值口袋——这种发现应该按季度产出、不靠兴致。

产出：`reviews/review_machine_<年-季>.md`（一页即可）。

## 铁律

- **教训必须可推广**——描述成"一类情形"、不绑定具体股票。
- **复盘只对照事实与论点，不替过去的判断找借口**；同时**不因单次坏结果鞭打正确的流程**（resulting 两个方向都防）。
- **盲评的独立上下文是命门**——先读旧结论再复盘＝被锚定，和质检关同理。
- **打不了分的预测不许写**——写进 predictions 的每条都要能在 check_by 当天明确判对错。
- 复盘是**后台沉淀**：dashboard 不显示，决策记录、台账、教训库都是 Claude 的工作文件。
