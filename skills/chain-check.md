# 技能：产业链质检关（chain-check —— 三道独立防线）

> 来历（2026-06-10）：单股有三道成文质检（check_numbers + 防幻觉 + 防成见），链曾只有"数字要标源"一句话和一次性的对抗审稿——结果中美分叉的错是用户逮的、2,600GW 旧数活到 2026 是核数 agent 顺带发现的。这一关把链的防错制度化。
> **触发：出闸门①/②页面前、或完整复盘后重大改版前，必过；🔴 清零才发布。** 季度 checkpoint（只拉指标判读）不必全过三道。

## 总则

- **独立上下文是命门**：每个检查 agent 只喂被查对象（闸门页 + nodes.json + indicators.json + chain_decision.json）和核查工具，**不喂作者的推理过程**——读了结论再复核＝共享盲点。
- **只挑错、不改写**：输出红黄牌清单；主 Claude 逐条裁决（采纳 / 部分采纳 / 驳回——驳回必须给证据级理由，不许以"原判断如此"为由）。
- 链没有 financials.csv 这样的本地真值，**数字核查必须联网回源**——所以防线一是联网 agent（可后台，频繁出工具调用天然保活）。
- 防卡死规矩同全局：grep 定位 + 小段 Read、频繁小步工具调用、禁整读大文件。
- 三道防线**并行**起（互不通气），收齐再裁决。

## 防线一 · 数字与时效核查 agent（防幻觉、防过期）

角色：对抗性核查员，默认"无据"。对象：闸门页 + 三个 JSON 里每个**承重数字**（删掉它结论会变的那种）。

查四件事：
1. **回源**：每个数字能否联网回查到出处？来源等级（一手统计/机构报告/媒体转引/自媒体）与 nodes.json 标注的 source、confidence 一致吗？BOM/成本栈/拆解类数字是否**双源**（只有单源必须显式标"单源+置信度"，没标＝🔴）。
2. **时效**（2,600GW 教训专设）：数据时点多旧？承重数字 >12 个月标 🟡；>24 个月、或已知来源有年度更新版（如 LBNL/Wood Mac 年报）而页面还在用旧版＝🔴。检查 as_of 字段有没有诚实标注。
3. **跨文件一致性**：同一个数字在 页面 / nodes.json / indicators.json 基线 / chain_decision 预测阈值 四处是否一致——基线改了、阈值没跟着改＝🔴（交期从 4 年修到 3 年时就发生过，靠人工记得才对齐）。
4. **算术抽查**：占比加总、单位换算（$/MMBtu→¢/kWh 这类）自己重算一遍。

输出：每条【位置 + 原文数字 + 核查结果 + 真值/出处 + 怎么改】，分 🔴 必改（错数/无据/被新版取代/跨文件打架）/ 🟡 存疑（单源/偏旧/口径含糊）/ ✅ 抽查通过样本。**最后一行：通过 / 不通过（任一 🔴 即不通过）。**

## 防线二 · 结构红队 agent（防判断盲区）

角色：唯一职责＝**推翻环节判断**。不查数字（防线一的事），攻击推理。按链研究的已知失败模式逐一进攻：

1. **租金被判成护城河**（最高发）：每个被判"持久"的环节，重走四问——在建产能真扩不出来？替代技术 S 曲线多远？最大买方能否前向整合/扶二供？瓶颈持续期多长？（电力底座差点把变压器/燃机当护城河的教训。）
2. **适用边界 / 地理外推**：每个结论是谁的命题？要素价格（气/电/原料）换个市场还成立吗？制度环境（电网体制/管制/贸易壁垒）依赖写明了吗？（中美分叉教训。）
3. **漏环节 / 漏暗线**：价值迁移有没有更大的暗线没画（BESS 釜底抽薪差点漏）？生态博弈（谁在商品化谁的互补品）漏了谁？边界定义漏了一级子链吗？
4. **需求台账攻击**：自下而上 × 自上而下两向对得上吗？母变量（如 capex/收入比）的反方证据找全了吗？数量级模型里哪个乘数最可疑？
5. **内部矛盾**：第五层"持久"判定与第四层"扩张顶部"位置矛盾吗？与利润守恒的迁移方向矛盾吗？scorecard 的"为什么值得研究"是 variant perception 还是共识复读？
6. **越界检查**：有没有溜进个股 verdict/目标区间/买卖名单（铁律红线）？环节定价温度计有没有标数据时点与聚合口径？

输出：3-6 条攻击，每条【攻击点 + 依据（数据/机制/判例）+ 若我对、判断该改成什么】，最后自评本轮攻击 强/中/弱。**红队只攻击、不和稀泥。**

## 防线三 · 完备性走查 agent（防无声留白）

角色：拿规格清单逐条对交付物——"说好要有的，都在吗"：

- **闸门①**：□ 需求台账节（两向核算+交叉）□ scorecard 每个候选有领先指标列 □ 每环节五层体检摘要 □ 数据诚实交底节（哪些没覆盖/哪些存疑）□ 一级子链边界论证（电力/软件生态没漏）
- **闸门②**：□ 四、五层都跑了（不是只拆成本）□ 适用边界节 □ 替代威胁时间表 □ 成本栈给的是区间 □ 交接区公司清单经独立核查+代码复核
- **知识文件**：□ nodes.json / indicators.json 与页面同步（页面有的承重判断卡里都有）□ 每条关键判断有 prediction 四元组 + 挂指标 □ next_checkpoint 在未来 □ chain.json 进度准确
- **无声留白扫描**：逐节问"这一节的数字从哪来的"——看起来覆盖全了、实际没查的，揪出来标明。

输出：缺项清单，🔴（规格必有而缺）/ 🟡（可补可标注）。**最后一行：通过 / 不通过。**

## 流程（主 Claude 操作）

1. 闸门页草稿 + JSON 就绪后，**并行**起三个独立 agent（防线一必联网；二、三本地为主可联网）。
2. 收三份清单 → 逐条裁决改稿 → 🔴 清零 → 跑 `inline_chain_assets.py` → 发布 → `refresh_dashboard.py`。
3. 红队拦到的真问题，记一条进 `reviews/CHAIN_LESSONS.md`（质检关拦截＝E 类升级的正面样本）；反复出现的失败模式升级进防线二的攻击清单。

## 配套 · 采集 agent 结构化输出规范（流水线 A 阶段）

链研究的标准 agent 流水线（详见 industry-chain.md『标准 agent 流水线』节）里，采集阶段的硬规矩：

- **任务书必须给 schema**：要求输出 nodes.json 节点卡片段（或 indicators 的 series 数据点），**不是散文**——结构化输出才能机器合并、被防线一核查。
- **每个数字必带四件套**：`{value, as_of, source(URL), confidence}`；查不到＝null + 列入 missing 清单，**绝不无声留白**。
- **按主题分工并行**：供给侧（产能/在建/capex/融资潮）、需求侧（量价分解）、技术路线（替代 S 曲线）、价格与交期——单个 agent 范围窄、频繁出工具调用（防卡死），联网类可后台。
- **主 Claude 合并片段进 nodes.json 之后才动笔判断**——采集可以外包，判断永远不外包。
